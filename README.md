# 산업·운영 설비 센서 이상 탐지 MVP

다변량 설비 센서 데이터를 이용해 정상 운전 패턴에서 벗어난 시간 구간을 탐지하고, 이상 점수와 상태를 API로 제공하는 개인 프로젝트입니다.

현재는 프로젝트 착수 단계입니다. 데이터 검증과 탐색을 먼저 수행한 뒤 통계 기준선과 Isolation Forest를 비교하고, 선택한 모델을 FastAPI로 제공합니다.

## 1. 프로젝트 개요

설비 운영 담당자가 여러 센서 그래프를 계속 확인하기는 어렵습니다. 이 프로젝트는 일정 시간 동안 수집된 센서 값을 분석해 확인이 필요한 구간을 선별하는 것을 목표로 합니다.

| 구분 | 내용 |
|---|---|
| 사용자 | 설비 상태를 확인하고 정비 우선순위를 판단하는 운영 담당자 |
| 입력 | 타임스탬프가 포함된 다변량 센서 시계열 |
| 처리 단위 | 일정 길이의 시간 구간(window) |
| 출력 | 이상 점수, 정상·이상 상태, 모델 버전 |
| 1차 모델 | 통계 기반 기준선, Isolation Forest |
| 제공 방식 | FastAPI 추론 API |

### 핵심 질문

1. 현재 센서 구간은 정상 범위에서 벗어났는가?
2. 모델의 이상 점수는 얼마인가?
3. 실제 알려진 이상 사건을 얼마나 탐지했는가?
4. 하루에 불필요한 경보가 몇 번 발생하는가?

## 2. 프로젝트 목표

```text
원천 센서 데이터
→ 데이터 품질 검증
→ 시간 구간별 특징 생성
→ 통계 기준선과 Isolation Forest 비교
→ 이상 사건 및 오탐 평가
→ 모델 저장
→ FastAPI 추론
→ 모델 버전과 예측 로그 기록
```

1차 MVP의 목표는 정확한 고장 시각이나 잔여 수명을 예측하는 것이 아닙니다. 정상 운전 패턴에서 벗어난 **이상 시간 구간을 탐지하는 것**이 목표입니다.

## 3. 데이터

### MetroPT-3

- 데이터 출처: [UCI MetroPT-3 Dataset](https://archive.ics.uci.edu/dataset/791/metropt%203%20dataset)
- 관련 설명: [MetroPT: A benchmark dataset for predictive maintenance](https://www.nature.com/articles/s41597-022-01877-3)
- 데이터 성격: 도시철도 공기 압축기 시스템에서 수집된 실제 운용 센서 시계열
- 규모: UCI 기준 약 151만 행, 15개 변수, 약 208MB
- 신호 예시: 압력, 온도, 모터 전류, 밸브·스위치 상태
- 라이선스: CC BY 4.0

이 데이터는 실제 설비에서 수집됐지만, 본 프로젝트는 공개된 정적 데이터를 이용한 재현형 MVP입니다. 실제 실시간 운영 시스템은 아닙니다.

UCI 자료와 관련 논문에서 설명하는 전체 MetroPT 자료의 기간과 범위가 완전히 같다고 가정하지 않습니다. 센서 의미와 고장·정비 구간은 내려받은 공식 설명 자료를 기준으로 정리할 예정입니다.

## 4. 분석 및 모델링 계획

### 4.1 데이터 품질 검증

다음 항목을 우선 확인합니다.

- 타임스탬프 파싱 및 시간순 정렬
- 중복 타임스탬프와 중복 행
- 센서별 결측값
- 관측 간격과 장시간 수집 공백
- 연속형 센서의 최솟값·최댓값·분위수
- 디지털 센서의 예상 값 범위
- 장시간 값이 변하지 않는 센서

### 4.2 시간 구간 특징

초기 후보는 1분 구간이지만, 실제 수집 주기와 설비 동작 패턴을 확인한 뒤 30초·1분·5분 구간을 비교합니다.

연속형 센서의 1차 특징 후보:

- 평균
- 표준편차
- 최솟값
- 최댓값
- 구간 처음과 끝의 차이

디지털 센서의 1차 특징 후보:

- 활성 비율
- 상태 전환 횟수
- 마지막 상태

### 4.3 데이터 분할

시계열의 미래 정보가 학습 과정에 유입되지 않도록 무작위 분할을 사용하지 않습니다.

| 구간 | 용도 | 기간 |
|---|---|---|
| 학습 | 정상 패턴 학습 | 공식 이상 구간 확인 후 결정 |
| 검증 | 특징 및 임계값 선택 | 공식 이상 구간 확인 후 결정 |
| 테스트 | 최종 성능 평가 | 공식 이상 구간 확인 후 결정 |

### 4.4 모델

1. 센서별 통계 또는 규칙 기반 기준선
2. Isolation Forest
3. 필요성이 확인될 때만 Autoencoder 비교

딥러닝 모델은 기준선 모델, API, 테스트가 완료된 이후에만 검토합니다.

## 5. 평가 방법

정상 구간 비중이 높을 수 있으므로 Accuracy를 핵심 지표로 사용하지 않습니다.

| 지표 | 확인할 내용 |
|---|---|
| Precision | 발생한 경보 중 실제 이상 비율 |
| Recall | 실제 이상 구간 중 탐지한 비율 |
| F1 | Precision과 Recall의 균형 |
| False alarms/day | 하루 평균 오탐 경보 수 |
| Event detection rate | 실제 이상 사건 단위 탐지율 |
| Detection lead time | 이상 사건보다 얼마나 먼저 탐지했는지 |

모델의 원시 점수를 바로 정상·이상으로 해석하지 않고, 검증 기간에서 탐지율과 일일 오탐 횟수를 비교해 임계값을 결정합니다.

## 6. API 계획

FastAPI를 사용해 다음 엔드포인트를 구현할 예정입니다.

| Method | Endpoint | 기능 |
|---|---|---|
| `GET` | `/health` | 서버 상태 확인 |
| `POST` | `/predict` | 센서 구간의 이상 점수와 상태 반환 |
| `GET` | `/model-info` | 모델명, 버전, 특징, 임계값 반환 |

예상 응답 형식:

```json
{
  "equipment_id": "metropt3-demo",
  "window_end": "2022-01-01T00:01:00",
  "anomaly_score": 0.82,
  "status": "anomaly",
  "threshold": 0.71,
  "model_version": "iforest-0.1.0"
}
```

위 값은 API 형식을 설명하기 위한 예시이며 실제 모델 결과가 아닙니다.

## 12. 제외 범위

1차 MVP에서는 다음 기능을 구현하지 않습니다.

- 정확한 고장 시각 또는 잔여 수명 예측
- 실시간 센서 스트리밍 인프라
- 강화학습 기반 설비 제어
- LLM/RAG
- 복잡한 프론트엔드
- Kubernetes, Airflow, Feature Store
- 자동 재학습과 클라우드 배포 자동화

## 13. 한계

- 실제 설비에 연결된 실시간 시스템이 아니라 공개 정적 데이터 기반 MVP임
- 공개된 고장·정비 기록의 범위에 따라 평가 가능한 사건이 제한될 수 있음
- 비지도 모델의 이상 점수가 반드시 실제 고장을 의미하지는 않음
- 현업 적용 전에는 설비 전문가의 검증과 경보 정책 설계가 필요함
